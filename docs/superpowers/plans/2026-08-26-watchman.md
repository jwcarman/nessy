# Watchman Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Spring Boot starter that wires a durable, observed Nessy harness from a `DataSource`, Boot's `ObservationRegistry` and beans; and a long-running "watchman" example that does timer-driven rounds on a Linux box, parks remediations for human approval, and shows them on a page.

**Architecture:** `nessy-spring-boot-starter` (auto-config + a `PendingApprovals` projection subscribed on the harness fact stream, persisted to a table); `nessy-examples/watchman` (Boot app: scheduled rounds, feature-detected Linux tools, Thymeleaf+HTMX page, actuator OTLP to LGTM, docker-compose for Postgres + LGTM).

**Tech Stack:** Spring Boot (current stable; root pom manages a version — report it), Spring MVC, Thymeleaf, HTMX, Testcontainers Postgres, Micrometer tracing bridge OTel, Java 25.

**Spec:** `docs/superpowers/specs/2026-08-26-watchman-design.md` (binding).

## Global Constraints

- The starter invents no Nessy vocabulary: it composes `Nessy.harness(...)`, `JdbcSubstrate`, `DefaultContinuum` + `JdbcContinuumRepository`, `ModelDiscovery`, `HarnessConfig.observationRegistry`, `harnessObserver`. New public types are only: the auto-configuration class, `NessyProperties`, `PendingApproval` (record), `PendingApprovalsRepository`, and the `PendingApprovals` observer — all in `org.jwcarman.nessy.spring.boot`.
- Every bean is `@ConditionalOnMissingBean`; a `DataSource` present ⇒ durable stores, absent ⇒ in-memory.
- No `@SuppressWarnings`; no star imports; sealed switches exhaustive, no `default`; S5778; S5841; no mocking library (hand-written fakes; Spring's test slices are fine).
- Tests never shell out to the host: every tool takes a `CommandRunner` seam.
- `./mvnw -q clean verify` passes with no API key and no model network; Docker is required only for the Testcontainers tests, tagged like `DurableResumeTest`.
- One Maven process; warm scoped builds; `clean verify` once per task; `./mvnw license:format -Plicense && ./mvnw spotless:apply` before each commit.
